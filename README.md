# Screenshot testing benchmark

The same Android app screenshot tested with three tools:

| Branch | Tool | Version |
| --- | --- | --- |
| [`mugshot`](../../tree/mugshot) | [Mugshot](https://github.com/TRazDev/Mugshot) | 3.4.2 |
| [`paparazzi`](../../tree/paparazzi) | [Paparazzi](https://github.com/cashapp/paparazzi) | 2.0.0-alpha05 |
| [`compose-preview-screenshot-testing`](../../tree/compose-preview-screenshot-testing) | [Compose Preview Screenshot Testing](https://developer.android.com/studio/preview/compose-screenshot-testing) | 0.0.1-alpha16 |

`main` is the app with no screenshot testing at all, so `git diff main..<branch>` is exactly what
each tool needed.

## The app

30 Gradle modules: a design system and 29 feature modules that depend on it. They hold 293 screens
built from Material 3 components plus 6 component catalogues, each with a `@Preview`, for 299
previews in total. Everything is generated by [`tools/generate.py`](tools/generate.py) from a fixed
seed, so every branch has identical screens.

Every preview is screenshotted in the same 24 configurations:

- four devices: a Pixel 10 (411 × 923 dp at 420 dpi), a Pixel Fold (701 × 841 dp at 420 dpi), a
  Pixel Tablet (1280 × 800 dp at 320 dpi) and the Pixel 10 in landscape
- light and dark
- font scales of 1, 1.5 and 2

That's 7,176 screenshots per tool.

## What each branch adds

| Tool | How the previews become screenshots |
| --- | --- |
| Mugshot | `@Mugshot` and `@MugshotMatrix` on each existing preview. A KSP processor generates the test. |
| Paparazzi | One JUnit test class per module, parameterised with TestParameterInjector over a list of that module's previews, the four devices, the two themes and the three font scales. |
| Compose Preview Screenshot Testing | One file per module in the `screenshotTest` source set: a multi-preview annotation with the 24 configurations, and a `@PreviewTest` function per preview that calls the existing preview. |

The app's previews are the same on every branch, and each tool reuses them rather than
redrawing the screens.

To count the lines each branch adds:

```bash
python3 tools/count_setup_code.py
```

## Running the benchmark

```bash
git worktree add runs/mugshot mugshot
git worktree add --detach runs/mugshot-downscale-1 mugshot
echo "uk.co.fractalmotion.mugshot.downscale=1" >> runs/mugshot-downscale-1/gradle.properties
git worktree add runs/paparazzi paparazzi
git worktree add runs/compose-preview compose-preview-screenshot-testing

python3 tools/benchmark.py --runs runs --rounds 3
```

[`tools/benchmark.py`](tools/benchmark.py) compiles every checkout first, untimed. Then, for each
tool, it records the golden images once and verifies them three times. Every timed build starts
with the Gradle daemon stopped, runs with `--no-build-cache`, and uses `--rerun` on the screenshot
tasks only, so the time is rendering and comparing rather than compiling. The order of the tools
rotates in each verify round, because whichever build runs first on a quiet machine has an
advantage.

Results go to `results/results.csv`, one row per build, with the wall-clock time, the number of
tests and failures from the JUnit reports, the summed test time, and the number and size of the
golden images.

Mugshot runs twice. Its default renders a third of the device's resolution; `mugshot-downscale-1`
renders at full resolution, which is closer to what the other two tools render.

## Regenerating the app

```bash
python3 tools/generate.py --tool none              # main
python3 tools/generate.py --tool mugshot           # mugshot
python3 tools/generate.py --tool paparazzi         # paparazzi
python3 tools/generate.py --tool compose-preview   # compose-preview-screenshot-testing
```

`--features`, `--min-screens` and `--max-screens` change the size of the app.
